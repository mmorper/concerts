# Morperhaus Concert Archives - AI Assistant Documentation

## Overview

Personal concert archive spanning 1984-2027. Interactive web application with 185 concerts, 258 artists, 80 venues.

**Live Site:** https://concerts.morperhaus.org
**Technology:** React SPA with D3.js visualizations, Leaflet maps, Tailwind UI
**Data Format:** Structured JSON with normalized entity names

---

## AI Access (MCP Server & Ask the Archive)

Beyond the raw JSON below, the archive is available to AI agents and assistants two ways. Both are
strictly grounded — every number, date, and name comes from the archive's own data, never invented.

### MCP Server (Model Context Protocol)
**Endpoint:** https://concerts.morperhaus.org/mcp
**Connect / about:** https://concerts.morperhaus.org/about-mcp
A remote MCP server that exposes the archive as structured tools, so an assistant can answer
grounded questions without scraping. Tools: `search_concerts`, `get_artist_history`,
`get_venue_history`, `get_concert_setlist`, `get_media`, `get_archive_top_songs`,
`get_archive_info`, `on_this_day`, `surprise_me`, `get_career_position`, `get_career_shape`, and a
freeform `query` escape hatch. `get_media` returns the owner's photos and clips as links to the exact
frame, never the images themselves. Each tool result ends with an "Open on the site" line of deep
links to the entities mentioned.

The two career tools read `album-eras.json` — the join between attendance and discography. They
answer where an artist stood in their own arc on a given night (`get_career_position`) and how the
whole archive falls across four decades of album cycles (`get_career_shape`), including the nights
a band was seen before the record they'd be remembered for existed.

### Ask the Archive (in-app search and chat)
**URL:** https://concerts.morperhaus.org/?scene=ask (`/ask` redirects there)
The last scene on the site, and a search box available from every scene (⌘K, or `/`). It reads
as search first:
- **Typing** shows instant matches for bands, venues, songs, years and clips, with counts. These
  come from the site's own data with no model call.
- **Asking** a question gets a sentence or two of prose, then an exhibit card: an act across every
  night, one night beside its setlist, a ranking, a gallery of the owner's photos, or a clip. Every
  number comes from the same tools the MCP server uses.
- **Follow-ups:** under an answer, one or two next questions (the setlist, the first time, the
  photos). Each is checked to have an answer before it is offered.
- **Ideas:** a photo banner in the search overlay and a carousel in the scene, led by a show from
  today's date in an earlier year when there is one.

**Remember:** this is ONE person's concert attendance history. That person is **Mike Morper**, the
archive's owner — so "Mike," "Mike Morper," "the owner," and the archive's own first person all mean
the same person, and every concert on record is one he attended. A question like "How many times has
Mike seen the Cure?" is a question about the Cure: answer it from that artist's history. Mike is on
no bill in here, so never look him up as a performer. Treat "not in the archive" as "not attended,"
never as "doesn't exist."

## Content Scope & Authority

### Personal Experience (Subjective)
- Concert attendance records (which shows attended, when, with whom)
- Personal memories and liner notes
- Subjective genre classifications
- Commentary and reflections

### Authoritative Data (Objective)
- Venue locations (latitude/longitude)
- Venue addresses and operational status
- Artist setlists (via setlist.fm API)
- Concert dates and lineups (cross-referenced with concertarchives.org)
- Genre taxonomy (primary/subgenres)
- Artist discographies (via MusicBrainz API - 11,524+ albums)

**Important:** This is ONE person's concert history, not a comprehensive database of all concerts by these artists.

### Album Eras
**URL:** https://concerts.morperhaus.org/data/album-eras.json
**Records:** 249 artists — the join between 40 years of attendance and the discography
**Source:** derived from `discography.json` + `concerts.json` (no API calls)
**What it answers:** where an artist stood in their arc on a given night, and what had not happened yet.
**Note:** covers openers as well as headliners. Restricting it to headliners left 22.3% of song→album pairs unattributable.
**Schema:**
```json
{
  "concerts": {
    "concert-21": {
      "artistKey": "depeche-mode",
      "currentAlbum": { "title": "Music for the Masses", "mbid": "...", "releaseDate": "1987-09-28" },
      "albumsBefore": 5,
      "albumsAfter": 9,
      "careerYear": 8,
      "yearsBeforeDebut": null,
      "definingAlbum": { "title": "Violator", "releaseDate": "1990-03-19", "topTrackCount": 3, "topTrackTotal": 5 },
      "definingAlbumAhead": true,
      "definingAlbumMonthsAway": 20
    }
  },
  "artists": { "depeche-mode": { "displayName": "Depeche Mode", "studioAlbumCount": 15, "studioAlbums": [], "erasSeen": [] } }
}
```

### Song → Album Attribution
**URL:** https://concerts.morperhaus.org/data/song-albums.json
**Records:** 1,811 of 2,027 unique artist+song pairs (89.3%)
**Source:** three tiers — `artists-top-tracks.json` (267), MusicBrainz (1,429), iTunes Search (35)
**What it answers:** which studio album a song performed live came off.
**Key format:** `artistKey::folded-song-title`. Derive it with `songAlbumKey()` from `scripts/utils/song-title.ts` — a caller that folds differently matches nothing while looking like it simply found nothing.

**Two properties that matter when reading this file:**
- **`releaseDate` precision varies.** 1,545 entries are full dates, 158 are `YYYY-MM`, 108 are bare `YYYY`. Any gap measured against it must respect that width — a 14-day claim against a month-precision date is undefined, not merely imprecise.
- **The album is the EARLIEST studio album carrying the song**, which is not always where the song first appeared. A standalone single that later landed on an album attributes to that album. The file supports claims about the *album*, never about when the song came into existence.

**Schema:**
```json
{
  "version": "1.0.0",
  "generatedAt": "2026-08-08T18:17:15.354Z",
  "songs": {
    "depeche-mode::just-cant-get-enough": {
      "songTitle": "Just Can't Get Enough",
      "albumTitle": "Speak & Spell",
      "mbid": "7a0e0366-91f4-3444-b45a-83b158004165",
      "releaseDate": "1981-10-05",
      "coverAvailable": true,
      "matchTier": 0
    },
    "prophets-of-rage::prophets-of-rage": {
      "songTitle": "Prophets of Rage",
      "albumTitle": "It Takes a Nation of Millions to Hold Us Back",
      "mbid": "01921d99-9d15-3fce-8734-46e58327cfb7",
      "releaseDate": "1988-06-28",
      "coverAvailable": true,
      "matchTier": 0,
      "isCover": true,
      "originalArtistKey": "public-enemy"
    }
  }
}
```

### Photos & Clips (Media Index)
**URL:** https://concerts.morperhaus.org/data/media-index.json
**Source:** the owner's own photos and video clips from nights in the archive. Not every show has them. They are excluded from AI training; see Usage Policy.
**What it answers:** which photos and clips exist for a night or an act, and how to link to one.

**How to read it:**
- **Only entries with a `url` are published.** An entry whose `url` is null is not public, so leave it out of any count.
- **Credit the entry's own `artist`, never the night's headliner.** Many nights have openers, and a night's frames are not all of one act. A null `artist` is a frame of the room: a marquee, an exterior, a stub.
- **`url` differs by kind.** A photo's is relative to the site. A clip's is a full URL, with a `poster` image beside it.
- **`song` on a clip is confirmed by the owner.** Not every clip has one.

**Link to one:** `/?scene=artists&artist={artistNormalized}&show={date}&photo={mediaId}`. See Entity Deep Links below. For a room frame, use any act on that night's bill.

**In tool results:** six MCP tools add a "Media on the site" line with the counts of published photos and clips, and any clip song titles: `search_concerts`, `get_artist_history`, `get_venue_history`, `get_concert_setlist`, `on_this_day`, and `surprise_me`. The line sits above "Open on the site". Ask's tool results carry the same line. No line means nothing is published for that result. "I can't check right now" means the index could not be read, not that nothing exists.

**Schema:**
```json
{
  "version": 1,
  "generated": "2026-11-02T00:49:54.121Z",
  "assets": [
    {
      "kind": "image",
      "url": "/images/shows/2026-09-16-thompson-twins-10.jpg",
      "date": "2026-09-16",
      "artist": "Thompson Twins",
      "artistNormalized": "thompson-twins"
    },
    {
      "kind": "video",
      "url": "https://media.morperhaus.org/videos/2016-09-03-howard-jones-01.mp4?v=a9edc1c3deae",
      "poster": "https://media.morperhaus.org/posters/2016-09-03-howard-jones-01.jpg?v=87cf5c8b2ebe",
      "date": "2016-09-03",
      "artist": "Howard Jones",
      "artistNormalized": "howard-jones",
      "duration": 15,
      "song": "The Human Touch"
    }
  ]
}
```

## Deep Linking System

All entities are deep-linkable via query parameters:

### Scene Navigation
The site has 6 scenes, in this order: Timeline, Venues, Geography, Genres, Artists, Ask the Archive.
- Timeline: `/?scene=timeline`
- Venues: `/?scene=venues`
- Geography: `/?scene=geography`
- Genres: `/?scene=genres`
- Artists: `/?scene=artists`
- Ask the Archive: `/?scene=ask`

### Entity Deep Links
- Artist: `/?scene=artists&artist={normalized-name}`
  Example: https://concerts.morperhaus.org/?scene=artists&artist=depeche-mode

- Setlist for one night: `/?scene=artists&artist={normalized-name}&show={YYYY-MM-DD}`
  Example: https://concerts.morperhaus.org/?scene=artists&artist=nile-rodgers&show=2026-07-31
  Opens the artist's gatefold with that concert's setlist expanded. The date is the
  concert date and is unique across the archive. Purely additive — an artist link
  without `show` behaves exactly as before, and an unresolvable date falls back to
  the artist view. Only ~2/3 of concerts have a setlist on record; the sitemap lists
  only those.

- One photo or clip from a night: `/?scene=artists&artist={normalized-name}&show={YYYY-MM-DD}&photo={mediaId}`
  Example: https://concerts.morperhaus.org/?scene=artists&artist=thompson-twins&show=2026-09-16&photo=thompson-twins-10
  Opens the artist's gatefold with the Photos panel on that image. `mediaId` is the
  published filename without its date or extension: `2026-09-16-thompson-twins-10.jpg`
  is `thompson-twins-10`. A clip also ends in `-video`: `2016-09-03-howard-jones-01.mp4`
  is `howard-jones-01-video`. `artist` decides whose gatefold opens, and a gatefold holds
  that act's frames and the night's room frames. A value that matches nothing opens the
  panel on its first image.

- Venue (Network): `/?scene=venues&venue={normalized-name}`
  Example: https://concerts.morperhaus.org/?scene=venues&venue=9-30-club

- Venue (Map): `/?scene=geography&venue={normalized-name}`
  Example: https://concerts.morperhaus.org/?scene=geography&venue=9-30-club

- Venue + Artist: `/?scene=venues&venue={venue}&artist={artist}`
  Example: https://concerts.morperhaus.org/?scene=venues&venue=9-30-club&artist=depeche-mode

### Normalization Rules
Entity names are normalized for URLs:
1. Convert to lowercase
2. Replace spaces and special characters with hyphens
3. Collapse multiple hyphens
4. Strip leading/trailing hyphens

Examples:
- "Depeche Mode" → `depeche-mode`
- "9:30 Club" → `9-30-club`
- "The English Beat" → `the-english-beat`

## Page Structure & Semantic Hierarchy

### Scene Navigation
The site is one page of full-viewport snap-scroll scenes, in the order below. Titles are what
crawlers are served. Counts in them are computed from `concerts.json` on every request, so they are
shown here as patterns.

#### 1. Timeline (`/?scene=timeline`)
**Title:** "{concerts} Concerts ({first year}-{last year}) | Morperhaus Concert Archives"
**H1:** "Concert Archive", with "{concerts} shows across {span}" under it
- A D3.js timeline with one marker per year, sized by how many shows that year had
- Hover a year for a preview; click it to fan out that year's concert cards

---

#### 2. Venues (`/?scene=venues`)
**Title:** "{venues} Concert Venues | Morperhaus Concert Archives"
**H1:** "The Venues"
- A force-directed network: venue nodes sized by show count, linked to the acts seen there
- Toggle between the 10 most-visited venues and all of them
- Click a venue to expand its headliners and openers and spotlight its connections

---

#### 3. Geography (`/?scene=geography`)
**Title:** "Concert Map: {venues} Venues Across North America | Morperhaus"
**H1:** "The Geography", with "{cities} cities across the map" under it
- A Leaflet map with a dark theme and clustered venue markers
- Region tabs: All, California, DC Area
- Marker popups carry the venue photo (Google Places), its shows, and a legacy badge for venues
  that have closed or been demolished

---

#### 4. Genres (`/?scene=genres`)
**Title:** "Music Genres Explored | Morperhaus Concert Archives"
**H1:** "The Music", with "Watch taste evolve decade by decade" under it
- A treemap of genres by show count, with a year slider that can play through the years

---

#### 5. Artists (`/?scene=artists`)
**Title:** "{artists} Artists I've Seen Live | Morperhaus Concert Archives"
**H1:** "The Artists", with "{artists} artists · {concerts} concerts" under it
- A searchable mosaic of album-style cards, one per act
- A card opens into a gatefold: every night seen, each night's setlist, the owner's photos and
  clips from those nights, audio previews, upcoming tour dates, and liner notes where one exists

---

#### 6. Ask the Archive (`/?scene=ask`)
**Title:** "Ask the Archive | Morperhaus Concert Archives"
**H1:** "That's over forty years. Now ask me about it."
- A search box that opens the Ask overlay (see AI Access above)
- A carousel of ideas to ask about, led by today's date in an earlier year when there is a show on it
- A link to connect the archive to Claude through the MCP server

#### How It Works (`/how-it-works`)
**Title:** "How It Works | Morperhaus Concert Archives"
**Purpose:** Interactive explainer showing how a single concert entry flows through the data enrichment pipeline

**What it does:**
- User selects an artist, venue, and date (or watches an auto-run featured example)
- The page animates the full enrichment cascade tier-by-tier: structural parsing → geographic enrichment → artist identity → audio previews → setlist/performance data
- Each tier reveals which APIs are called, what data fields are populated, and how many data points are generated
- Ends with a live preview of the archive's scenes fed by that concert's enriched data

**Tiers explained:**
- Tier 1 — Structural: date parsing, decade/day-of-week computation, normalized slugs
- Tier 2 — Geographic: lat/lng, venue address, venue photos (Google Places)
- Tier 3 — Artist Identity: bio, genres, images (TheAudioDB, then Deezer when TheAudioDB has no match)
- Tier 4 — Audio: 30-second previews, album art (Apple Music / iTunes)
- Tier 5 — Performance: setlists, covers, tour context (setlist.fm / Ticketmaster)
- Tier 6 — Output: the interactive archive scenes

**Meta Tags (bot-rendered):**
- Dynamic title and description including current concert count and year span
- URL: https://concerts.morperhaus.org/how-it-works

## Interaction Patterns

### Scene Navigation
- Vertical snap-scroll between full-viewport scenes
- Smooth transitions with Framer Motion
- Deep linking preserves scroll position to correct scene
- Cross-scene navigation (e.g., click venue in map → venue network)

### Entity Exploration
- **Timeline:** Click year dots to expand cards showing all concerts
- **Venues Network:** Click venue nodes to expand and show artists/openers
- **Map:** Click markers to open popups with photos and details
- **Genres:** Drag the year slider, or let it play, to watch the mix change
- **Artists:** Search, or click a card, to open its gatefold
- **Ask the Archive:** ⌘K or `/` from any scene opens the search; a match or a question opens its answer

### Data Fetching
- Initial load: Base HTML + static JSON files (concerts.json, artists-metadata.json, venues-metadata.json)
- Lazy loading: Artist images, venue photos, the owner's photos and clips, loaded on demand
- Setlists: pre-fetched from setlist.fm into setlists-cache.json, so the site doesn't call setlist.fm per visit
- Audio previews: iTunes preview links, pre-fetched into artists-top-tracks.json
- Called from the browser when needed: Ticketmaster, for upcoming tour dates
- Ask: answers come from the Ask Worker at `/api/ask/*`. The MCP server is at `/mcp`
- Discography: discography.json feeds the data pipeline (album eras, song attribution). The site doesn't load it

## Common Queries & Answers

### "How many times has Morperhaus seen [artist]?"
Query: `concerts.json` → filter by `headlinerNormalized` or `openers` array
Answer format: "X times" + list of dates/venues

### "What venues has Morperhaus visited in [city/state]?"
Query: `concerts.json` → filter by `city` or `state` → unique `venue` values
Answer format: List of venues with concert counts

### "What's the most-attended venue?"
Query: `concerts.json` → count by `venueNormalized` → sort descending
Answer: Venue name + concert count

### "What artists has Morperhaus seen the most?"
Query: `concerts.json` → count each act's nights as headliner OR opener → sort descending.
Counting `headlinerNormalized` alone undercounts any act that has opened. The MCP tool
`get_archive_info` returns the same tally.
Answer: Artist name + concert count + date range

### "What genres does Morperhaus prefer?"
Query: `concerts.json` → count by `genre` → sort descending
Answer: Genre distribution (note: subjective classification)

### "Show me concerts from [year]"
Query: `concerts.json` → filter by `year`
Answer: Chronological list with headliner, venue, date

### "What's the venue location for [venue]?"
Query: `venues-metadata.json` → lookup by normalized name
Answer: Address, coordinates, city/state (authoritative)

### "What setlists are available?"
Query: `setlists-cache.json` (pre-fetched from setlist.fm), or the MCP tool `get_concert_setlist`
Answer: Roughly two-thirds of nights have one. The sitemap lists only those nights' links

### "What albums has [artist] released?"
Query: `discography.json` → lookup by normalized artist name
Answer: List of albums with release dates, types, track counts

## Features

### Interactive Visualizations
1. **Timeline** - D3.js scrollable timeline with hover previews
2. **Venue Network** - Force-directed graph showing artist/venue relationships
3. **Geography** - Leaflet map with venue markers and photos
4. **Genres** - A genre treemap with a year slider
5. **Artist Mosaic** - Album-style cards with gatefold animations
6. **Ask the Archive** - Search and tool-grounded chat over the whole archive

### Data Integration
- **setlist.fm API** - Setlists for attended concerts, pre-fetched
- **Ticketmaster API** - Upcoming tour dates
- **Google Places API** - Venue photos and addresses
- **TheAudioDB, then Deezer** - Artist photos and biographies. A result is used only when its name matches the act
- **iTunes Search** - Audio previews and album artwork
- **MusicBrainz API** - Artist discographies (11,524+ albums)

### Navigation
- Snap-scroll between full-viewport scenes
- Deep linking to any entity
- Cross-scene navigation (e.g., venue click in map → venue network)
- URL-based state management

## Technical Details

### Technology Stack
- **Frontend:** React 18 + TypeScript 7 + Vite 8
- **Styling:** Tailwind CSS 4
- **Visualization:** D3.js 7 + Framer Motion 11
- **Mapping:** Leaflet 1.9
- **Analytics:** Google Analytics 4 + Cloudflare Web Analytics
- **Hosting:** Cloudflare Pages for the site. Cloudflare Workers for the MCP server, Ask the Archive, and the link previews crawlers see
- **CI/CD:** GitHub Actions

### Data Pipeline
1. Google Sheets (master concert list), re-fetched every Monday
2. Fetch & normalize script
3. Enrich with external APIs (setlist.fm, Google Places, TheAudioDB, Deezer, iTunes, MusicBrainz, Ticketmaster)
4. Validate schema and relationships
5. Generate derived data (stats, album eras, song attribution)
6. Build static JSON files

### Build Process
- Data refresh: `npm run build-data`
- Development server: `npm run dev`
- Production build: `npm run build`
- Deployment: Automatic via Cloudflare Pages on push to main
